> 定位：本地优先、离线可用、以「日程 + 知识库」为核心的个人管理系统。  
> 本文档只做澄清与设计，**不含代码**。等你确认后再进入阶段 1。

## 0. 一个必须先拍板的冲突：技术栈形态

你的长期偏好是 **「零外链」——单 HTML 文件、无 CDN、可离线运行**（来自「个人工作台」记账本的既定约定）。  
但你这次给的 spec 是 **React + Vite + Tauri + Capacitor + SQLite** 的重工程化方案。两者不能同时满分，需要先选：

| 方案                                     | 形态                                                   | 优点                                    | 代价                                                           |
| -------------------------------------- | ---------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------ |
| **A. 单文件零外链**                          | 一个 `index.html`，内联 JS/CSS，IndexedDB 存储               | 免构建、双击即开、手机/电脑/离线全通、分发最简单             | 无 SQLite、无原生壳（Tauri/Capacitor 免谈）、文件系统受限、代码组织靠约定、单文件会膨胀到几 MB |
| **B. Vite + React + TS，构建产物「零外链」**（推荐） | 源码多文件工程化，构建成离线 PWA，产出可塞进 Tauri / Capacitor 的 WebView | 工程化 + 可维护 + 适配器好替换 + **运行时依然零外链、可离线** | 需要 Node 构建步骤；不是「一个文件」                                        |
| **C. Tauri + React + SQLite（桌面优先）**    | 桌面原生 + 真 SQLite + 真本地文件                              | 文件系统最强、通知最可靠                          | 移动端要另起一套，起步最慢                                                |

**我的推荐：B。** 它同时满足你真正在意的两件事——**运行时无外网请求、断网可用**，同时保住工程化和后续上 Tauri/Capacitor 的可能。  
所谓「零外链」落到 B 上是三条硬约束：① 所有依赖打进 bundle，禁止任何 CDN/远程字体/远程图标；② 运行时默认零网络请求（AI、同步默认关闭）；③ 产物可被单目录拷贝走。  
如果你坚持「必须是一个 .html 文件」，请选 A，我会按单文件重写方案（功能要砍掉 OCR/SQLite/原生通知）。

### 2.2 关键机制

| 机制            | 做法                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------- |
| **本地优先**      | 所有写操作先落 IndexedDB（+ OPFS 存附件二进制），UI 直接读本地，永远不等网络                                         |
| **软删除 + 修订号** | 每条记录带 `deletedAt`、`rev`、`updatedAt`，为将来同步合并与冲突检测留后路（阶段 1 就埋好，成本几乎为零）                     |
| **AI 不静默写入**  | AI 只能产出 `Draft`（草稿表），经 `drafts` 页面确认/编辑后才 `commit` 成正式 `item`/`note`，全程可回溯到 `AIParseJob` |
| **适配器**       | 每个 adapter 一个 interface + 注册表，设置页可切换；未配置即降级（如关掉 AI → 走规则解析；关掉同步 → 只本地）                   |
| **离线 PWA**    | Service Worker 预缓存全部静态资源；运行时零 CDN                                                        |
| **导出**        | Markdown（含 front-matter）/ JSON（全库）/ ICS（日程）；一键完整备份 zip                                   |

## 3. 数据模型

### 3.1 设计决策：单表多态

`Task / Event / Course / Assignment / ClassAffair / Activity / Exam / Meeting` **合并为一张 `items` 表**，用 `type` 判别。  
理由：视图（日历、今日、看板、搜索、时间轴）需要跨类型统一查询与排序；单表 + `type` 索引比 8 张表 union 简单一个数量级。  
类型专属字段（学分、教室、任课教师、班费金额…）放 `extra: Record<string, unknown>`，并在 `domain/item.ts` 里为每个 type 定义校验器。

### 3.2 核心类型（TypeScript）

```ts
type ID = string;            // uuid v4
type ISO = string;           // ISO 8601

interface BaseEntity {
  id: ID;
  createdAt: ISO;
  updatedAt: ISO;
  deletedAt?: ISO | null;    // 软删除（同步合并用）
  rev: number;               // 本地修订号，每次写 +1
}

type ItemType =
  | 'task' | 'todo' | 'assignment' | 'course' | 'classAffair'
  | 'activity' | 'exam' | 'meeting' | 'custom';

type ItemStatus = 'notStarted' | 'inProgress' | 'done' | 'cancelled' | 'postponed';
type Priority = 0 | 1 | 2 | 3 | 4;   // 无 / 低 / 中 / 高 / 紧急

interface Recurrence {
  freq: 'daily' | 'weekly' | 'monthly' | 'yearly' | 'custom';
  interval: number;
  byWeekday?: number[];      // 0=周日
  weeks?: number[];          // 教学周次，如 [1,3,5,7,9]
  weekParity?: 'all' | 'odd' | 'even';   // 单双周
  until?: ISO;
  rrule?: string;            // 兼容标准 RRULE 导出
}

interface ScheduleItem extends BaseEntity {
  type: ItemType;
  title: string;
  startAt?: ISO | null;
  dueAt?: ISO | null;
  allDay: boolean;
  priority: Priority;
  status: ItemStatus;
  completedAt?: ISO | null;
  tags: ID[];
  noteIds: ID[];
  attachmentIds: ID[];
  sourceId?: ID | null;
  courseId?: ID | null;      // 关联的 course 型 item
  classId?: ID | null;
  reminderIds: ID[];
  recurrence?: Recurrence | null;
  location?: string;
  remark?: string;
  extra?: Record<string, unknown>;
  // AI 相关
  origin: 'manual' | 'ai' | 'import';
  pendingConfirm?: string[];               // 需人工确认的字段名
  confidence?: Record<string, number>;     // 字段置信度 0~1
}

interface Note extends BaseEntity {
  title: string;
  path: string;              // 虚拟路径：/课程/高数/第3章.md
  content: string;           // Markdown 原文
  tags: ID[];
  itemIds: ID[];
  attachmentIds: ID[];
  backlinks: ID[];           // 冗余字段，由 links 表维护
  sourceId?: ID | null;
  pinned: boolean;
}

interface Attachment extends BaseEntity {
  name: string;
  mime: string;
  size: number;
  storageKey: string;        // OPFS/文件系统路径
  hash?: string;             // 内容哈希，去重
  extractedText?: string;    // PDF/Word/OCR 抽取结果（可加密）
  extractedAt?: ISO;
  ownerRefs: Ref[];          // 反向关联
}

type Ref =
  | { kind: 'item'; id: ID }
  | { kind: 'note'; id: ID }
  | { kind: 'attachment'; id: ID };

interface Tag extends BaseEntity {
  name: string;              // 唯一
  color?: string;
  parentId?: ID | null;      // 支持 #班级/班费 层级
}

interface Link extends BaseEntity {   // 双链
  fromType: 'note' | 'item';
  fromId: ID;
  toType: 'note' | 'item';
  toId: ID;
  context?: string;          // 链接所在片段，用于图谱悬停预览
}

interface Source extends BaseEntity {
  kind: 'text' | 'image' | 'pdf' | 'word' | 'markdown' | 'url' | 'manual';
  rawText?: string;          // 原文快照（敏感，可加密/可不清空）
  url?: string;
  attachmentId?: ID | null;
  capturedAt: ISO;
}

interface Reminder extends BaseEntity {
  itemId: ID;
  triggerAt: ISO;
  offsetMinutes: number;     // 相对截止提前量
  fired: boolean;
  channel: 'web' | 'system';
}

interface AIParseJob extends BaseEntity {
  sourceId: ID;
  provider: string;
  status: 'queued' | 'running' | 'success' | 'failed' | 'retrying';
  retries: number;
  inputKind: Source['kind'];
  outputDraftIds: ID[];
  error?: string;            // 只记错误，不记正文
  startedAt?: ISO;
  finishedAt?: ISO;
}

interface Draft extends BaseEntity {   // AI 草稿，确认前不进正式表
  jobId: ID;
  target: 'item' | 'note';
  payload: Partial<ScheduleItem> | Partial<Note>;
  pendingConfirm: string[];
  confidence: Record<string, number>;
  state: 'pending' | 'accepted' | 'edited' | 'rejected';
}

interface SyncLog extends BaseEntity {
  adapter: string;
  startedAt: ISO;
  finishedAt?: ISO;
  pushed: number; pulled: number;
  status: 'success' | 'failed' | 'conflict';
  message?: string;
}

interface Conflict extends BaseEntity {
  entityType: 'item' | 'note' | 'attachment' | 'tag';
  entityId: ID;
  localRev: number; remoteRev: number;
  localSnapshot: unknown; remoteSnapshot: unknown;
  resolution?: 'local' | 'remote' | 'both' | 'manual';
  resolvedAt?: ISO;
}

interface OutboxOp extends BaseEntity { // 离线变更队列（阶段 4 启用，阶段 1 就建表）
  seq: number;
  entityType: string; entityId: ID;
  op: 'create' | 'update' | 'delete';
  payload: unknown;
  status: 'pending' | 'synced' | 'failed';
}
```

### 3.3 表与索引（Dexie）

| 表                        | 主键  | 主要索引                                                                                         |
| ------------------------ | --- | -------------------------------------------------------------------------------------------- |
| `items`                  | id  | `type`, `status`, `dueAt`, `startAt`, `[type+dueAt]`, `[status+dueAt]`, `updatedAt`, `*tags` |
| `notes`                  | id  | `path`, `updatedAt`, `*tags`                                                                 |
| `links`                  | id  | `fromId`, `toId`, `[fromType+fromId]`                                                        |
| `attachments`            | id  | `hash`, `name`                                                                               |
| `tags`                   | id  | `&name`, `parentId`                                                                          |
| `sources`                | id  | `kind`, `capturedAt`                                                                         |
| `reminders`              | id  | `itemId`, `triggerAt`, `fired`                                                               |
| `drafts`                 | id  | `jobId`, `state`                                                                             |
| `aiJobs`                 | id  | `status`, `createdAt`                                                                        |
| `outbox`                 | id  | `seq`, `status`                                                                              |
| `conflicts` / `syncLogs` | id  | `status`                                                                                     |
| `meta`                   | key | —（配置、schema 版本、上次同步游标）                                                                       |


### 3.4 关系一览

- `Note ↔ Note`：多对多双链（`links`）
- `Note ↔ Item`：多对多（`noteIds` / `itemIds` 双向冗余 + `links`）
- `Attachment → Note|Item|Attachment`：`ownerRefs`
- `Tag → *`：多对多，所有主实体带 `tags: ID[]`
- `Source → Draft → Item|Note`：`AIParseJob` 串起来，全链路可回溯
- `Item → Reminder`：一对多

## 6. 已知限制（提前说清，不假装纯前端能干）

1. **Web 端没有可靠后台提醒**：浏览器不允许后台常驻定时器。Web 阶段只能「打开页面时触发 + 浏览器通知」。真正准时的本地通知必须靠 Tauri/Capacitor（阶段 6）。
2. **WebDAV 同步需要服务端 CORS 头**，否则浏览器直连会被拦；坚果云/群晖等需确认。Git 适配器在纯浏览器下需要 GitHub API + Token（等价云端，非「纯本地」）。Supabase/自托管 **必须联网**，不是本地优先的必要件。
3. **浏览器文件系统受限**：OPFS 可用但不是用户的真实文件夹。想要「我的笔记就是磁盘上的 .md 文件」，必须上桌面壳（Tauri）。
4. **OCR 中文包 ~15MB**，需要一次性下载并缓存；移动端性能较差，长图建议先用云端 AI 视觉模型。
5. **语义搜索需要 embedding**：本地 embedding 要下模型（几十 MB）；用云端则违背离线优先。默认方案：语义搜索可选、默认关闭，主检索靠全文 + 结构化过滤。
6. **AI 解析准确率不是 100%**，所以「草稿 + 确认」是硬约束，永远不会自动写入。
