# 怎么配置 GitHub 同步（给朋友）

> **先说结论：这一步是可选的。**
> 不开同步，软件完全能用 —— 只是数据只在你这一台设备上。
> 想让**手机和电脑的数据互通**，才需要配这个。
>
> 全程约 5 分钟，只要会点鼠标，不需要懂技术。

---

## 零、先想清楚要不要开

| 你的情况 | 建议 |
|---|---|
| 只用一台电脑 | **不用开**。偶尔用「设置 → 数据 → 一键备份」导个 JSON 就行 |
| 电脑 + 手机都要用，想自动同步 | 开，看下去 |
| 只有两台电脑 | 开，或者更简单：同步适配器选「本地文件夹」，指向 OneDrive/微盘同步目录 |

⚠️ **一个仓库只服务一个人。** 两个人共用一个仓库会互相覆盖对方的数据。
所以：**每个人建自己的仓库，别共用。**

---

## 一、你需要一个 GitHub 账号

- 有 → 直接看第二步
- 没有 → 打开 <https://github.com> 注册，免费，只需要邮箱。
  （国内访问偶尔慢，多刷新几次；连不上就先看第九节的替代方案）

---

## 二、建一个**私有**仓库

1. 登录 GitHub，点右上角 **「+」→ New repository**
2. 填：
   - **Repository name**：随便起，比如 `personal-os-sync`
   - **Private** ← ⚠️ **一定要选这个**
     （选 Public 等于把你的日程和笔记发到公网上，谁都能看）
   - 其他都不用动，**不要**勾 "Add a README file"
3. 点 **Create repository**

建好后会看到一个空仓库页面。地址栏形如：
`https://github.com/你的用户名/personal-os-sync`

**记住「你的用户名/personal-os-sync」这一段**，等下要填。

---

## 三、生成一把钥匙（Token）

软件需要一把"钥匙"才能读写你的仓库。这把钥匙只有你能看见。

### 方式 A：Fine-grained token（推荐，权限更干净）

1. 右上角**头像** → **Settings**
2. 左侧最下面 **Developer settings**
3. **Personal access tokens** → **Fine-grained tokens**
4. **Generate new token**
5. 填：
   - **Token name**：随便，比如 `personal-os`
   - **Expiration**：选 `90 days`（到期前重新生成一次即可；别选「No expiration」，丢了不好收拾）
   - **Repository access**：选 **Only select repositories** → 下拉里勾你刚建的那个仓库
6. Permissions（权限）—— **这一步是最容易错的地方**：
   - 点 **Repository permissions** 展开
   - 找到 **Contents**
   - 把它从默认的 `Read-only` 改成 **Read and write**
   - ⚠️ 不改这里，后面会出现「测试连接成功，但一同步就报 401」
7. 拉到最下面 **Generate token**
8. **立刻复制那串字符**（形如 `github_pat_11A...`）
   —— **只显示这一次**，关掉页面就再也看不到了。

### 方式 B：Classic token（更简单，权限给得粗）

1. 头像 → **Settings** → **Developer settings**
2. **Personal access tokens** → **Tokens (classic)**
3. **Generate new token (classic)**
4. 勾 **`repo`**（勾它会自动带上它下面那几个子项）
5. **Generate token** → **立刻复制**（形如 `ghp_...`）

> 两种方式都行。方式 A 更讲究，方式 B 更省事。

## 四、填进软件

打开个人工作台 → **设置** → 往下找 **「同步」**：

| 字段 | 填什么 |
|---|---|
| 适配器 | 选 **GitHub** |
| 仓库（owner/repo） | `你的用户名/personal-os-sync`<br>⚠️ **不是网址！** 不要填 `https://github.com/...`，只填 `用户名/仓库名` 这一段 |
| 分支 | `main`（GitHub 新建仓库默认就是这个） |
| 密码 / Token / Key | 粘贴刚才复制的那串 |
| 每 15 分钟自动同步一次 | 想自动就勾上（只在软件打开时生效） |

填完点 **「测试连接」**。

- 成功 → 会提示「仓库可访问」+ 你的 Token 权限
- 失败 → 看第六节的报错对照表

---

## 五、第一次同步，顺序很重要

**做得对：** 一次就好。
**做反了：** 会多出一堆重复条目（虽然能清理，但麻烦）。

正确顺序：

1. 在**数据多的那台**设备上（一般是电脑），点「同步」
   → 它会把你现有的数据推到 GitHub
2. 再到**另一台**设备（手机/另一台电脑），打开网页版，
   填**同样的**仓库和 Token，点「同步」
   → 它会先拉下来再合并

如果两边都已经各录了一堆，同步后出现重复条目：
去 `设置 → 重复数据清理`，一键去掉多余的。

## 六、报错对照表

| 提示 | 多半是 | 怎么办 |
|---|---|---|
| **404** | ① 仓库名填成了网址<br>② 仓库不存在<br>③ 仓库是私有的，Token 没权限 | 仓库名只填 `用户名/仓库名`；确认 Token 勾了这个仓库 |
| **401**（测试能过，同步失败） | Token 只有读权限 | 回到第三步，把 **Contents 改成 Read and write**，重新生成 |
| **403** | 权限不足，或被限流 | 检查权限；等几分钟再试 |
| **409** | 远端文件在别处被改过，或分支名不对 | 确认分支是 `main`；去 GitHub 网页把仓库里那个 json 文件删掉，重新同步 |
| **tags ConstraintError** | 老版本 bug | 升级到 0.2.0 及以上 |
| **Fail to fetch** | 网络问题 / 桌面版被 CSP 拦 | 0.2.0 已修；确认是最新版 |

## 七、安全上的几句话

- **仓库必须 Private。** 再说一次，Public = 公开你的日记。
- **Token 不要发给任何人**，包括作者。它只存在你自己电脑的加密库里。
- **一个仓库只服务一个人。** 情侣/室友别共用一个仓库。
- Token 到期了怎么办：重新生成一把，回软件里粘贴新的，老的自动作废。

---

## 八、手机端怎么配

手机打开网页版（`.../app/`）→ 设置 → 同步 → 填**同样的**仓库和 Token → 测试连接 → 同步。

注意：**手机端没有语义搜索**（模型太大跑不动），其他都一样。

---

## 九、嫌麻烦 / GitHub 连不上

| 替代方案 | 怎么做 | 适合 |
|---|---|---|
| **本地文件夹** | 适配器选「本地文件夹」，指向 OneDrive / 微盘 / iCloud 的同步目录 | 两台电脑之间同步，最省事 |
| **只做备份** | 不开同步，每周 `设置 → 数据 → 一键备份` 导一份 JSON 存网盘 | 只用一台设备 |
| **手动搬数据** | 一台导出 JSON → 发给另一台 → 「从备份恢复」选「覆盖」 | 偶尔搬一次 |

同步的本质就是"把一份快照放在你自己的地方"。
GitHub 只是其中一个选项，不是必需品。

---

## 十、还是没配好

1. `设置 → 一键体检` —— 会告诉你是哪一项没填对
2. `设置 → 关于 → 导出诊断包` —— txt 里**不含**任何日程内容和你的 Token，可以放心发给作者
3. 把报错的**原话**截图发给我，比描述"它说不行"有用得多
