# 个人工作台 · 可分发化方案 v1（评审稿）

> 状态：**待评审，未动代码**
> 目标：把当前在你本机跑通的「自用开发版」，变成别人能**自己下载 → 自己安装 → 自己配置 → 自己用起来**的「可分发版」。
> 硬约束（已写入本方案所有设计）：
> 1. 代码里**不得出现**任何硬编码的 API Key、服务器地址、你本机的个人路径；
> 2. 用户数据**默认本地隔离**，不上传任何我们控制的服务器；
> 3. 若将来共用后端，**必须**有多租户隔离 + 权限；
> 4. 必须有**一键导出 / 备份 / 恢复**；
> 5. 发布物必须带**版本号 + CHANGELOG + 下载页**。

---

## 0. 一句话结论

**不要为了"分发"去造后端和账号体系。**

这个应用的全部价值主张就是「本地优先、数据在我自己手里」。正确做法是：把它做成 **零服务器 · 自带钥匙（BYOK）· 自带仓库（BYORepo）** 的桌面软件 —— 我们只分发一个**空壳 + 能力开关**，AI Key 用户自己填、同步仓库用户自己建、数据永远只落在用户自己的磁盘和自己的 GitHub 上。

这样：
- 我们的**边际成本 = 0**（不付 AI 钱、不付流量钱、不付服务器钱）；
- 我们的**法律责任最小**（不持有用户数据）；
- 用户**装完立刻能用**（不填任何东西也能用：规则解析 + 全文搜索 + 手动录入全可用）。

需要花钱/花时间的只有一件事：**让普通人装得上、跑得起来**（Windows 智能应用控制 + SmartScreen + 杀软），这是本方案的 P0 风险。

## 2. 现状体检：现在直接发出去会出什么问题

按「会不会让用户装不上 / 用不了 / 数据丢」排优先级。

### P0 —— 会直接导致失败，必须解决

| ID | 问题 | 现状 | 后果 | 解决方向 |
|---|---|---|---|---|
| **P0-1** | **Windows 智能应用控制（SAC）** | 你自己就踩过：SAC 会阻止未签名/无信誉的程序运行（你编译 Rust 时遇到 `os error 4551`） | 开启 SAC 的 Win11 新机**双击 exe 直接被拦**，用户完全不知道发生了什么 | ① 优先引导用 **MSI/NSIS 的 currentUser 安装**（系统对安装包的判定比裸 exe 宽松）；② 下载页必须写清"遇到蓝色/黄色拦截怎么点"；③ 长期：买 OV 证书 |
| **P0-2** | **SmartScreen 未签名警告** | 无代码签名证书 | 弹出"Windows 已保护你的电脑"，用户不敢点 | 下载页放**逐字 + 截图**的绕过指引（更多信息 → 仍要运行）；v2 买证书彻底解决 |
| **P0-3** | **语义搜索模型 / OCR 语言包缺** | `public/models`（bge-small-zh，22.9MB）靠 `npm run model:setup` 手动生成；tesseract 语言包运行时下载 | 别人装完，"语义搜索"点不动、OCR 慢/失败，且**没有任何提示告诉他们缺什么** | ① 桌面包**内置模型**；② 首启向导检测并提示"是否下载"；③ 所有能力缺失都要**给出可点击的原因说明**（你已经在 `embed.ts` / `ask.ts` 里做了 `reason`，要延伸到所有入口） |
| **P0-4** | **版本号与身份不是"你的"** | `tauri.conf.json` 里 `identifier: cn.workbuddy.personal-os`（是 WorkBuddy 的域名反写，不是你的）；版本 `0.1.0` 在 `package.json` 和 `tauri.conf.json` **各写一份** | ① 以后你做自动更新会跟别人冲突；② 改版本容易漏改，发布物与 CHANGELOG 对不上 | 改成你自己掌握的标识（如 `com.github.wzsl07.personal-os`）；版本**单一真相源**：以 `package.json` 为准，构建脚本同步写入 `tauri.conf.json` |
| **P0-5** | **没有 CHANGELOG / LICENSE / 隐私说明** | 无 | 不敢公开发；第三方库（pdf.js、tesseract.js、transformers.js、onnxruntime-web、MiniSearch 等）的许可义务未履行 | 见 §7 文档清单 |
| **P0-6** | **NSIS 默认要管理员权限** | `bundle.windows.nsis` 未配置，默认装到 Program Files | 公司电脑 / 校园机房 / 没管理员密码的用户**根本装不了** | `installMode: "currentUser"` → 装到 `%LOCALAPPDATA%`，免 UAC |

### P1 —— 不解决会"能用但很难受"

| ID | 问题 | 说明 | 解决方向 |
|---|---|---|---|
| P1-1 | 用户**找不到自己的数据在哪** | 数据在 WebView 的 AppData 目录下（`...\AppData\Roaming\<identifier>\`），肉眼不可见 | 设置页加「打开数据目录」按钮（Rust 命令 `open_data_dir`） |
| P1-2 | **没有一键备份** | 有 `exportSnapshot/importSnapshot`，但入口深、没有自动提醒 | 设置页「一键备份」+ 首次 7 天未备份的提醒 |
| P1-3 | **卸载会不会删数据不明确** | NSIS 卸载默认不清 AppData，但用户不知道 | 卸载页明确写"你的数据保留在 xxx，卸载不会删除" |
| P1-4 | **出问题无法自助诊断** | 用户报错只能截图 | 「导出诊断包」：版本号 + 系统 + 各能力自检结果 + 最近错误日志（**默认脱敏**） |
| P1-5 | **CSP 放得太宽** | `connect-src ... https:`（你为修 GitHub 同步临时放开） | 分发前收紧：显式列出 `api.github.com`、AI 自定义域名由用户配置时动态提示，而不是全开 |
| P1-6 | **Alt+Space 全局快捷键** | 与输入法/其他软件抢键 | 改成默认关闭 + 设置页可改键 |
| P1-7 | **数据只有本地一份** | 硬盘坏 = 全丢 | 首启向导把「开启同步 / 自动备份」作为**推荐步骤**（不强制） |
| P1-8 | 备份文件含加密的 API Key，换机器恢复后解不开 | `crypto.ts` 用设备密钥材料加密，导出到别的设备无法解密 | 导出时明确提示"密钥不会随备份迁移，恢复后需重新填写"；口令模式下提示输入口令 |

## 3. 目标架构

### 3.1 总览

```
┌─────────────── 用户自己的机器 ───────────────┐
│                                              │
│  ┌── 桌面端（主形态，Windows NSIS）────────┐  │
│  │  个人工作台.exe                         │  │
│  │   ├─ 内置：本地向量模型 bge-small-zh    │  │
│  │   ├─ 内置：tesseract 中文/英文语言包    │  │
│  │   └─ 数据：IndexedDB（本机 AppData）    │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ┌── 网页端 PWA（零安装试用）─────────────┐  │
│  │  浏览器 profile 内 IndexedDB（同源）    │  │
│  └────────────────────────────────────────┘  │
│                                              │
│  ┌── 便携版 ZIP（装不上的兜底）───────────┐  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
             │                    │
             │  用户自己的凭据     │  用户自己的凭据
             ▼                    ▼
   ┌──────────────────┐  ┌──────────────────────┐
   │ AI（可选，BYOK） │  │ 同步（可选，BYORepo）│
   │ DeepSeek / 兼容  │  │ GitHub 私有仓库       │
   │ / Ollama 本地    │  │ 用户自己的 Token      │
   └──────────────────┘  └──────────────────────┘
        ▲ 钱：用户出          ▲ 钱：GitHub 免费

   ☁️ 我们的服务器：不存在。
```

### 3.2 能力三档（这是"谁付费"问题的答案）

| 能力 | 档位 A：纯离线（默认，0 元） | 档位 B：自带钥匙（用户自付） | 档位 C：托管代付（**不做**） |
|---|---|---|---|
| 自然语言解析 | `rule.ts` 规则解析 | 用户填 Key → 大模型解析 | ❌ |
| 语义搜索 | 本地 bge-small-zh（`embed.ts`） | — | ❌ |
| 查询改写 / 问答 | 关闭（有明确原因提示） | 用户填 Key → 可用 | ❌ |
| OCR | 本地 tesseract.js | 用户填自己的云 OCR Key（可选） | ❌ |
| 同步 | 导出/导入文件 | 用户自己的 GitHub 仓库 + Token | ❌ |

**设计原则：任何能力缺失都必须显示"缺什么 + 点这里去填"，而不是灰掉/报错。** 你已经在 `SemanticPanel.tsx` / `ask.ts` 里做了这件事，要把它做成**全局统一的能力门面**（见 §6.2 的 `CapabilityGate`）。

### 3.3 数据隔离

| 场景 | 隔离机制 | 是否满足要求 |
|---|---|---|
| 同一台电脑，不同 Windows 用户 | 数据在各自 `%APPDATA%`/`%LOCALAPPDATA%`，系统级隔离 | ✅ 天然满足 |
| 不同电脑 | 各存各的，只有用户主动同步才互通 | ✅ |
| 网页 PWA 同一浏览器不同 profile | 浏览器 profile 隔离 | ✅ |
| 网页 PWA 同一 profile | **共享同一份 IndexedDB** | ⚠️ 需在设置页明确提示"公用电脑请用浏览器多用户/隐私窗口" |
| 多人共用一个 GitHub 仓库 | **会互相覆盖** | ⚠️ 必须在同步设置明确写：**一个仓库只服务一个人** |

**结论：默认隔离已满足要求；只需补两条说明文字 + 一个 PWA 共用电脑提示。**

### 3.4 如果将来要做共享后端（v2+，本方案不做）

一旦引入，必须同时满足（缺一不可）：

1. **多租户**：所有表带 `tenant_id` / `user_id`，服务端**强制**按身份过滤，不信任客户端传的 id；
2. **权限**：至少 `owner / readonly` 两级；分享链接带有效期与可撤销；
3. **密钥不落地**：用户的 AI Key **永不上行**服务端，只存本地（或服务端加密且我们无法解密）；
4. **端到端加密**（可选但推荐）：同步内容在客户端用用户口令加密，服务端只见密文；
5. **审计日志**：谁在什么时候读了什么；
6. **配额与限流**：防止一个人打爆成本；
7. **数据导出与注销**：随时一键导出全部数据、一键删除账号及全部数据。

在这 7 条没做完之前，**不要**做共享后端。

## 4. 打包 / 部署 / 发布流程

### 4.1 版本号策略（单一真相源）

```
package.json  "version": "0.1.0"   ← 唯一真相源
        │
        └─ scripts/sync-version.mjs ──► 写入 src-tauri/tauri.conf.json
                                    ──► 写入 src/core/version.ts（页面"关于"里显示）
                                    ──► 写入 CHANGELOG.md 顶部（若该版本段不存在则报错提醒）
```

- 语义化版本：`MAJOR.MINOR.PATCH`，0.x 阶段 PATCH = bug 修复，MINOR = 新功能。
- 发布物命名：`个人工作台-<版本>-win-x64-安装包.exe`、`个人工作台-<版本>-win-x64-便携版.zip`。

### 4.2 构建流程（本机 / 或 GitHub Actions）

```bash
# 0) 前置（一次性）
npm run model:setup     # 生成 public/models + public/libs（语义模型 + transformers 运行时）
npm run ocr:setup       # 生成 tesseract 语言包
npm run icons           # 生成全部图标

# 1) 同步版本号
node scripts/sync-version.mjs

# 2) 前端 + 桌面打包
npm run tauri:build     # 产物：src-tauri/target/release/bundle/nsis/*.exe

# 3) 生成便携版 ZIP（把安装后的目录内容打包）
node scripts/make-portable.mjs

# 4) 生成校验和与发布说明
node scripts/make-release.mjs   # SHA256 + latest.json（自动更新用） + release-notes

# 5) 发布
#    → GitHub Release（打 tag v0.1.0，上传：安装包 / 便携版 / SHA256.txt / CHANGELOG 片段）
#    → 更新下载页 docs-site/index.html 里的版本号与下载链接
```

### 4.3 签名

| 阶段 | 做法 | 成本 | 效果 |
|---|---|---|---|
| **v1（本方案）** | 不签名。改用：① NSIS `currentUser`（免 UAC）；② 下载页放**截图级**的 SmartScreen / SAC 绕过指引；③ 提供便携版兜底 | 0 元 | 大部分人能装上，少数人被拦 |
| **v2** | 买 **OV 代码签名证书**（个人也能买，约 ¥500–1500/年） | 中 | SmartScreen 快速积累信誉，警告大幅减少 |
| **v3（若做成产品）** | EV 证书（需企业资质，¥2000+/年，需 USB token） | 高 | 立即消除 SmartScreen 警告 |

> ⚠️ **注意**：Win11 的**智能应用控制（SAC）** 比 SmartScreen 更严格。你本机已经关掉它了，但**别人不会关**。必须在内测里专门验证"开启 SAC 的机器能否安装"。

### 4.4 自动更新

- **v1 不做。** 理由：Tauri 的 updater 必须配 `pubkey` 做签名校验，否则等于让所有用户自动下载并执行未签名代码，这是**安全倒退**。
- **v2 做**：`tauri-plugin-updater` + `TAURI_SIGNING_PRIVATE_KEY`（私钥只在你本机/CI secrets）
  - endpoints 指向 GitHub Releases 上的 `latest.json`
  - `dialog: true`，让用户自己决定何时更新
  - 更新前**自动触发一次本地备份**（防止更新丢数据）

### 4.5 发布渠道

- **主渠道**：GitHub Releases（免费、带 CDN、天然有 `latest.json` 托管位）
- **下载页**：一个**单文件静态 HTML**（沿用你的"零外链"原则），放：三形态下载按钮、版本号、更新日期、CHANGELOG 摘要、SHA256、系统要求、安装图文、常见问题（SmartScreen/SAC 怎么处理）。可用你已用的线上托管发布。
- **不做的**：应用商店（Microsoft Store 需开发者账号年费 + 签名 + 审核，v2 再说）

## 10. 拍板结果（2026-10-13 已确认）

| # | 议题 | 结论 | 落到的实现 |
|---|---|---|---|
| 1 | 应用标识 | `com.github.wzsl07.personal-os` | 已改。⚠️ 数据目录随之改变，旧数据需「导出 JSON → 新版恢复（覆盖）」迁移 |
| 2 | 分发范围 | **只给熟人朋友内测**，不做公开发布 | 法律文档做到"够用"即可（MIT + 第三方声明 + 隐私说明），不做下载页多语言/应用商店/公开 SEO |
| 3 | 代码签名证书 | **不买** | 靠三件套兜底：NSIS 免管理员 + 安装指南里的拦截处理图文 + 便携版 ZIP |
| 4 | 语义模型 | **随包内置** | 实测**本来就内置了**：`dist/` 里 model 24MB + libs 22MB，`frontendDist` 整体打进 exe，无需额外改造 |
| 5 | 网页版 / 手机端 | **保留，作为唯一手机入口** | 手机端没有别的路：手机装不了 exe，只能靠 HTTPS 网页版。详见 §11 |

### 11. 手机端：绕不开网页版

**结论：要让朋友在手机上用，就必须有一个公网 HTTPS 网址。**

| 方案 | 可行性 | 说明 |
|---|---|---|
| 手机装桌面版 | ❌ 不可能 | 手机是 Android/iOS，跑不了 Windows exe |
| 手机连你电脑的局域网地址 | ❌ 不可用 | 只能在同一 WiFi 下临时用，出门就断，且不信任的 HTTPS 会让 PWA 装不上 |
| **网页版 PWA（HTTPS）** | ✅ **唯一可行** | 手机浏览器打开网址 → 可"添加到主屏幕" → 数据存在手机本地 |

所以网页版**不是可选项，是手机端的唯一入口**。

需要注意的是：

- **数据不互通**，除非两端都配同步。手机上的数据存在手机浏览器的 profile 里，和电脑是两份；两边都指向同一个 GitHub 私有仓库才会同步。
- **手机端没有语义搜索**（22MB 向量模型在手机上跑不动），只有全文搜索。这是既定行为，应在界面上说清。
- **一个网址多人用是安全的**：每个人打开后数据只在自己的浏览器里，互不可见 —— 但如果两个人共用一部手机/同一个浏览器用户，就会看到同一份数据。
- 现在的地址是测试域名；给朋友用没问题的前提下可以直接给，**长期对外**建议换成你自己的域名。

### 附：本方案刻意**不做**的事（以及为什么）

| 不做 | 原因 |
|---|---|
| 自建服务器 / 账号体系 | 与"本地优先"定位冲突；引入成本、责任、合规负担；本方案下没有一项功能真正需要它 |

| 未签名就上自动更新 | 等于让所有用户自动执行未校验代码，是安全倒退 |
| 上应用商店 | 需开发者账号年费 + 签名 + 审核，当前阶段性价比低 |
| 现在做 macOS/Linux | 没有对应机器做真机验证，做出来的包无人能保证能跑 |
